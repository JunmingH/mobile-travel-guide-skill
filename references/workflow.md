# 工作流程与更新

## 新建

1. 读计划/问卷，列明成员、日期、交通住宿事实和缺项。已有材料可替代问卷。
2. 展示简要逐日草案，复用已获得的确认；明确“直接生成”可跳过讨论。保存实际确认原话。
3. `mobile.py init` 创建固定引擎与研究任务。用户级宿主项目配置是独立配置，不发布进仓库。
4. 对照工作台 `research/tasks/` 和 `research_status.py` 逐个完成来源、地点、日程、实用信息与媒体。
5. 需要下一步时运行工作台 `.mobile-runtime/scripts/advance_build.py WORKBENCH`；继续执行当前阶段，不把任务文件生成当完成。
6. `render` → `export` → `pwa`。检查手机版完整功能，查看生成图标并记录真实观察。
7. 原引擎 handoff 和手机检查通过后，再做授权的加密发布。

简要需求 JSON 可包含 destination、country、start_date、days、travelers、rhythm、interests、constraints、budget。保留用户补充字段，不用旧目的地资料填缺项。日期/酒店/航班未知时保持待确认。

## 接收新版计划

`snapshot` 为源数据及当前生成物建立私人备份。`import-plan` 保存原文件、正文提取文本、SHA-256、逐行差异和阅读限制。文本提取不代表图片、页眉或复杂版式已审阅；需要时用文档工具核对。

逐项比较：日期/顺序；参与人员；交通时间/航站楼；酒店；新增/删除地点；预约；休息；可选/必去变化。写一份短的变更说明，区分“文档明确变更”和“为实现该安排所作的必要校正”。例如 12:40 起飞且要求提前3小时，则目标到达09:40；不要继续沿用10:10并称提前3小时。

## 文件归属

| 内容 | 来源位置 | 生成结果 |
| --- | --- | --- |
| 旅行身份、概览、已知交通锚点 | `research/framing.json`、需求/决策记录 | profile、封面、航班栏目 |
| 逐日行程、道路/公交方案 | `research/itinerary.json` | 正文和旅行模式 |
| 地点、餐饮、购物与体验 | `research/places/` | 对应章节和地图 |
| 三语卡片、准备与贴士 | `research/modules/` | 语言、准备、提示 |
| 应用外壳和发布目标 | `mobile-app.json` | PWA / 加密发布 |

修改 owning pack 后编译；不要同时在 HTML、旅行模式和手写攻略维护三份事实。所有新增地点必须进入当日路线和对应介绍；可选地点若无地图标记，明确说明地图只展示主路线。

## 工作台身份

`handbook_id` 控制旅行工具数据命名空间。新增手册生成新 ID；更新保持原 ID。既有的 URL、namespace、数据库名和存储 schema 都是兼容约束。若真的需要迁移，先提供导出/恢复路径、测试旧数据，再执行用户已授权的迁移。

`configure` 只给已有工作台增加 PWA 配置，不替换其源引擎。若旧版 HTML 缺少完整版工具或媒体，先修原内容来源，不包装一个功能缺失的 HTML 并称完整。

## 文件直接交付

完整 `handbook-offline.html` 可以在允许本地 JavaScript 的浏览器/工具中使用。iPhone 文件预览器可能只显示静态内容；这与响应式排版不同。Safari 添加主屏幕的 PWA 需要 HTTPS 首次缓存，不能用 ZIP 绕过。若用户要首次也断网，确定本地运行容器后对那个容器验证，不继续承诺 Safari PWA 的安装流程。
